เว็บระบบกลุ่มและปุ่มเชิญสมาชิกขึ้นใช้งานบน homeserver แล้ว เก็บกิจกรรมเดิม 548 รายการและบัญชีเดิมไว้ครบ สำรองทั้งโค้ดและ SQLite ก่อนอัปเดต

ผู้จัดการ/เจ้าของกลุ่มเปิด **จัดการกลุ่ม → เชิญสมาชิก → ส่งคำเชิญทางอีเมล** กรอกอีเมล เลือกสิทธิ์และอายุคำเชิญ แล้วกด **ส่งคำเชิญ** ได้เลย ไม่มี checkbox ซ้ำ ส่วนลิงก์และรหัสเข้าร่วมสร้างเพื่อคัดลอกส่งเอง ผู้ส่งคือ Tutel Calendar <noreply@toomtoom.online> ผ่าน Brevo; รหัส SMTP เก็บเฉพาะ .env บนเซิร์ฟเวอร์

ยังไม่ได้ส่งเมลทดสอบ จึงยังไม่ยืนยันการได้รับจริง CSV ที่ยืนยันแล้วสร้างคำเชิญล่วงหน้าและเข้าคิวส่งอีเมลทีละคน ส่วนการเปลี่ยนระบบแจ้งเตือน Discord และ control panel หลักไปใช้ระบบกลุ่มยังไม่ได้เปิดใช้งานในการอัปเดตเว็บครั้งนี้ ข้อความที่ระบุว่าเป็นโค้ดในเครื่องเท่านั้นด้านล่างเป็นบันทึกก่อนการอัปเดตครั้งนี้

ฉบับ 10 ตุลาคม 2026 เว็บระบบกลุ่ม deploy แล้ว worker Discord เปิดบน homeserver แล้วและหยุดระบบเตือนเดิม ให้เชื่อมแต่ละช่องด้วยลิงก์กลุ่ม คู่มือนี้ใช้แทนคำอธิบายเดิมที่ถือว่ามีปฏิทินเดียว รายละเอียดเชิงเทคนิคเพิ่มเติมอยู่ใน GROUPS.md

## 1. แยกโปรเจกต์และข้อมูล

Tutel Calendar เก็บบัญชี กลุ่ม สมาชิก กิจกรรม คำเชิญ การตั้งค่า และงานแจ้งเตือน ส่วน Tutel Bot ดูแลเพลง วิทยุ การเชื่อม Discord การเลือกเครื่องที่ทำงาน และ control panel หลัก ทั้งสองติดต่อผ่าน API พร้อมกุญแจเฉพาะ ไม่เปิดไฟล์ SQLite เดียวกันจากหลายเครื่อง

```text
ผู้ใช้ -> เว็บ Calendar -> ตรวจ session/CSRF/สิทธิ์กลุ่ม -> SQLite
แอดมินหลัก -> control panel -> API จัดการ Calendar
บอทเครื่องที่ทำงาน -> รับงาน Calendar -> ส่ง Discord -> บันทึกผล
```

สมาชิกหนึ่งบัญชีอยู่ได้หลายกลุ่ม กิจกรรมและช่องแจ้งเตือนมี group_id ของตนเอง การรู้รหัสกลุ่มอื่นไม่ได้ทำให้เข้าถึงข้อมูลของกลุ่มนั้น

## 2. สร้างกลุ่มและสิทธิ์

ลงชื่อเข้าใช้แล้วกดสร้างกลุ่ม ระบุชื่อและ slug สำหรับลิงก์ กลุ่มใหม่เป็นส่วนตัว เปลี่ยนกลุ่มจากเมนูด้านบน ระบบจำกลุ่มล่าสุดและหมวดที่เลือกของสมาชิกในฐานข้อมูล ส่วนผู้ชมที่ยังไม่ login จำค่าแยกกลุ่มในเบราว์เซอร์

| บทบาท           | สิ่งที่ทำได้                                                                |
| --------------- | --------------------------------------------------------------------------- |
| สมาชิก          | ดูกิจกรรม ส่งข้อเสนอ แก้ข้อเสนอของตนที่ยังรออนุมัติ ตั้งเตือนส่วนตัว        |
| ผู้แก้ไข        | เหมือนสมาชิกและแก้กิจกรรมที่เผยแพร่แล้ว ใช้นโยบาย trusted ได้               |
| ผู้จัดการ       | อนุมัติ ดูแลสมาชิกทั่วไป ความน่าเชื่อถือ คำเชิญ การเตือนและช่องที่เชื่อมไว้ |
| เจ้าของ         | เพิ่มสิทธิ์ผู้จัดการ เปลี่ยนชื่อ/การเปิดดู โอนเจ้าของ                       |
| ผู้ดูแลระบบหลัก | จัดการทุกกลุ่มจาก control panel ส่วนตัว                                     |

กลุ่มส่วนตัวดูได้เฉพาะสมาชิก กลุ่มสาธารณะดูผ่าน /g/slug ได้ ไม่มีหน้าค้นหากลุ่มหรือขอสมัครเอง การระงับสมาชิกมีผลเฉพาะกลุ่ม เจ้าของต้องโอนเจ้าของก่อนตัดสิทธิ์ตน ผู้จัดการปฏิทินไม่ได้รับบัญชีหรือสิทธิ์ควบคุมเซิร์ฟเวอร์

## 3. เชิญสมาชิกและ CSV

เชิญได้ด้วยลิงก์ รหัสเข้ากลุ่ม หรืออีเมล กำหนดอายุ 1–30 วัน และจำนวนใช้ 1–500 ครั้ง ค่าเริ่มต้น 7 วัน/1 ครั้ง อีเมลใช้ได้ครั้งเดียว รหัสเข้ากลุ่มเป็นเลขฐานสิบหกสุ่ม 12 ตัว ไม่ใช่ PIN เดียวร่วมทุกกลุ่ม ฐานข้อมูลเก็บ hash ของ token ลิงก์จริงแสดงตอนสร้างเท่านั้น ยกเลิกคำเชิญได้ในรายการคำเชิญ

การเพิ่มคนด้วยเมลคือเตรียมคำเชิญไว้ ไม่สร้างบัญชีปลอม เมื่อเขา login ด้วยเมลที่ผู้ให้บริการยืนยันตรงกัน ระบบเพิ่มเข้ากลุ่มให้ สมาชิกที่ login อยู่รีเฟรชเพื่อรับคำเชิญใหม่ได้ คำเชิญไม่เปลี่ยนสิทธิ์เดิมและไม่ข้ามการระงับ

CSV ต้องมี email และใส่ name/role ได้ รองรับ UTF-8, BOM, ฟิลด์ใส่เครื่องหมายคำพูด จำกัด 500 แถว/100 KB ต้องตรวจตัวอย่างก่อนยืนยัน ถ้าเมลซ้ำหรือรูปแบบผิดจะไม่บันทึกทั้งชุด CSV ให้ได้แค่ member/editor:

```csv
email,name,role
student@parichat.skru.ac.th,นักศึกษา,member
editor@example.com,ผู้แก้ไข,editor
```

สร้างลิงก์หรือรหัสเชิญเพื่อคัดลอกได้โดยไม่ใช้ SMTP ส่วนคำเชิญอีเมลและ CSV ที่ยืนยันจะเข้าคิวส่งผ่าน SMTP ที่ตั้งบน homeserver แล้ว ไม่มีช่องติ๊กส่งอีเมลซ้ำ การสร้างคำเชิญยังไม่สร้างสมาชิกจนกว่าจะกดรับ และสถานะผู้ให้บริการรับเมลไม่ยืนยันว่าถึง inbox ทุกคน

## 4. บัญชี Google/Discord

ใช้ข้อมูลบัญชีพื้นฐาน ไม่มีการอ่าน Gmail หรือ Google Calendar รองรับ Google มหาวิทยาลัยรวม @parichat.skru.ac.th ต้องเป็นเมลที่ Google ยืนยัน พร้อม Gmail หรือ hosted domain ที่ยืนยันได้ ส่วน Discord ขอ identify และ email เพิ่ม อาจต้องยินยอมใหม่

เชื่อมบัญชีอีกผู้ให้บริการจากเมนูบัญชีขณะ login ต้องผ่าน OAuth สดและยังมี session ของบัญชีเดิม จึงไม่รวมบัญชีจากชื่อหรือเมลที่คล้ายกัน หากทั้งสองเคยสมัครแยก จะรวมสมาชิก กิจกรรม และแจ้งเตือนใน transaction เก็บสิทธิ์ที่สูงกว่าและสถานะระงับไว้ ยกเลิก session ของบัญชีที่ถูกย้าย

Session เป็นคุกกี้ HttpOnly และ Secure เมื่อใช้ HTTPS คำขอแก้ข้อมูลต้องผ่าน CSRF และตรวจ origin ส่วน API ระหว่างเซิร์ฟเวอร์ใช้กุญแจคนละชุดกับ session และ Discord bot token

## 5. เชื่อม Discord และตั้งเตือน

เมื่อเปิดระบบกลุ่ม ให้ใช้ /calendar connect ในช่องเป้าหมาย ผู้สั่งต้องมี Manage Server และบอทมี View Channel, Send Messages, Embed Links จะได้ลิงก์เฉพาะใช้ครั้งเดียวภายใน 10 นาที เปิดเว็บและ login/เชื่อมบัญชี Discord คนเดียวกับผู้สั่ง เลือกกลุ่มที่จัดการและยืนยัน กลุ่มจึงผูกกับช่องและดิสที่ออกลิงก์นั้นโดยตรง

ผู้ดูแลหลักเพิ่มช่องจาก panel ได้หลังตรวจสิทธิ์บอท ผู้จัดการกลุ่มแก้การเตือนหรือปิดช่องที่เชื่อมแล้วได้ แต่เปลี่ยนปลายทางเองตามอำเภอใจไม่ได้ กลุ่มหนึ่งมีได้หลายช่อง และช่องหนึ่งมีได้หลายกลุ่ม สมาชิกในช่อง Discord จะเห็นรายการของกลุ่มที่ผูก แม้เว็บกลุ่มเป็นส่วนตัว จึงต้องเลือกช่องให้ตรงสมาชิก

ค่าเริ่มต้นสรุปวันนี้ 07:00 และวันพรุ่งนี้ 12:00 ของวันก่อนหน้า ตามเวลาไทย เลือกหมวด สี และเปิดเตือนก่อนกิจกรรมแบบมีเวลาได้ แยกค่าต่อช่อง ปุ่มปฏิทินเปิดกลุ่ม/วันเดียวกัน และถ้าเป็นกิจกรรมเฉพาะจะเปิดรายละเอียดรายการนั้น กลุ่มส่วนตัวยังต้อง login

รวมกิจกรรมเป็นข้อความสรุป ไม่ส่งแยกทุกกิจกรรม รวมสูงสุดห้ากลุ่มต่อข้อความ หากเกินข้อจำกัด Discord จะแบ่งข้อความ รายการยาวแสดงลิงก์ดูทั้งหมด มีปุ่มส่งข้อความทดลอง แต่ต้องเห็นสถานะ sent/Message ID ก่อนจึงถือว่าส่งสำเร็จ

## 6. การส่งและสลับเครื่อง

เฉพาะบอทเครื่องที่ได้รับเลือกให้ทำงานรับงานทุก 15 วินาที แต่ละงานมีรหัสป้องกันซ้ำและรับสิทธิ์ส่งชั่วคราว 120 วินาที บันทึกก่อนเริ่มส่งและยืนยัน Message ID หลังส่ง

| สถานะ     | ความหมาย                                                    |
| --------- | ----------------------------------------------------------- |
| pending   | รอรับงาน                                                    |
| claimed   | เครื่องหนึ่งรับสิทธิ์ ถ้ายังไม่เริ่มส่งและหมดเวลารับใหม่ได้ |
| sending   | เริ่มส่งแล้ว เครื่องอื่นต้องไม่ส่งซ้ำทันที                  |
| sent      | ยืนยัน Message ID แล้ว                                      |
| failed    | ล้มเหลวที่ทราบ เช่นเข้าช่องไม่ได้ ตรวจแล้วลองใหม่เอง        |
| uncertain | อาจส่งแล้ว แต่ขาดการยืนยัน ต้องตรวจช่องก่อนลองใหม่          |
| expired   | พ้นเวลาที่ควรส่ง                                            |

เก็บตกการสร้างงานในห้านาที งานรอเกินหนึ่งชั่วโมงหมดอายุ ไม่รับประกัน exactly-once ระหว่างบริการอิสระ หากดับหลัง Discord รับข้อความแต่ก่อนยืนยันผลจะเป็น uncertain ระบบไม่ยิงซ้ำไม่สิ้นสุด แอดมินเห็นสถานะและต้องยืนยันว่าตรวจช่องแล้วก่อน retry

ถ้า homeserver ดับ บอท Oracle อาจรับหน้าที่เพลงได้ตามระบบเลือกเครื่องเดิม แต่ถ้า Calendar อยู่บนเครื่องที่ดับ ทั้งคู่จะรับงานใหม่ไม่ได้ เว็บไซต์/ฐานข้อมูล Calendar ยังไม่ย้ายไป Oracle อัตโนมัติ ต้องวางระบบสำรองแยก

## 7. Control panel หลัก

ใช้บัญชีผู้ดูแล panel เดิม เปิดจัดการทุกกลุ่ม จะเห็นสรุป กลุ่ม สมาชิกทั้งหมด/สิทธิ์แต่ละกลุ่ม รายชื่อคำเชิญ/CSV โอนเจ้าของ แก้และอนุมัติกิจกรรม ช่อง Discord/ส่งทดลอง งานแจ้งเตือน/ลองใหม่ และประวัติเปลี่ยนแปลง กิจกรรมนำเข้ายังแก้ไม่ได้ ต้องแก้ต้นทางระหว่างย้ายระบบ

เบราว์เซอร์ส่งผ่าน proxy ของ panel ที่ตรวจ session/admin/CSRF และเส้นทางที่อนุญาต ก่อนเรียก Calendar ด้วย CALENDAR_CONTROL_SECRET บนเซิร์ฟเวอร์ กุญแจไม่ออกไป JavaScript ส่วน CALENDAR_BOT_SECRET ใช้แค่ API รับงานและเชื่อมช่อง ไม่จัดการสมาชิกหรือกิจกรรม ใช้กุญแจต่างกันและเปิด panel ผ่านเครือข่ายส่วนตัว

หน้ารายการจำกัดผู้ใช้/กิจกรรม 1,000 รายการ คำเชิญ/งาน/ประวัติ 500 รายการ ยังไม่ใช่ระบบ export วิเคราะห์ข้อมูลแบบไม่จำกัด

## 8. ตั้งค่าและย้ายระบบ

ต้องใช้ Node.js 24 ขึ้นไป ติดตั้ง dependency แต่ละโฟลเดอร์แยกกัน ใน .env ของเครื่องนี้สร้างกุญแจสุ่มสองชุดที่ตรงกันระหว่างโปรเจกต์ไว้แล้ว อย่าส่งหรือ commit .env ตัวอย่างไม่มีค่าจริง

Bot ใช้ CALENDAR_SERVICE_URL และ CALENDAR_WEB_URL เป็น http://127.0.0.1:3100 สำหรับในเครื่อง และ CALENDAR_GROUPS_ENABLED=1 ไว้ก่อน เริ่มเว็บจาก D:/tutel-calendar ด้วย npm start โหมด demo ใช้เฉพาะ loopback โหมด OAuth จริงต้อง HTTPS และ ENABLE_DEMO=0 หากคนละเครื่องให้ใช้ URL HTTPS ที่ทั้งสองบอทเข้าถึง

ก่อนเปิดระบบจริง ต้องสำรอง SQLite แบบ consistent หรือหยุดโปรเซสก่อน เพราะไฟล์ WAL อาจยังมีข้อมูลใหม่ สำรองข้อมูลบอทต่างหาก สร้าง/ตรวจช่องผูกกลุ่มให้ครบ จากนั้นตั้ง CALENDAR_GROUPS_ENABLED=1 ในบอททั้งสองเครื่อง ลงทะเบียนคำสั่งและเริ่มบริการใหม่พร้อมแผนย้อนกลับ สวิตช์นี้แทน scheduler เดิมทั้งระบบ ไม่ใช่แยกกลุ่ม อย่าเปิดขณะยังมีช่องที่ใช้ระบบเก่า

ข้อมูลเดิมรักษา ID ย้ายเข้า cs-skru กลุ่มสาธารณะ สมาชิกและค่าเดิมย้ายครั้งเดียว ผู้จัดการเดิมถูกย้ายเป็นบัญชีดูแล Calendar หลัก ต้องทบทวนรายชื่อก่อนใช้งานจริง กลุ่มใหม่ไม่มีข้อมูลเดิมปน ระบบนำเข้ายังไม่ลบรายการตามต้นทางอัตโนมัติ ปิด importer/publisher เมื่อย้ายเสร็จ อย่าทำ sync วนสองทาง

โหมดใหม่คำสั่ง Calendar ส่งเข้ากระบวนการเว็บ การเพิ่ม/ลบรายการจากคำสั่งเก่าไม่ได้คงไว้ ในรอบนี้ยังไม่ได้อัปโหลด เปลี่ยน DNS/dashboard OAuth หรือรันการทดสอบจริง ก่อน cutover ต้องทดสอบสิทธิ์ข้ามกลุ่มและการส่งใน staging

## 9. โครงสร้างโค้ด

groups/ ดูแล schema สิทธิ์ คำเชิญ และเส้นทางกลุ่ม; auth/ ดูแล OAuth/session/เชื่อมบัญชี; events/ ตรวจและแก้กิจกรรม; members/ เก็บค่ารายกลุ่ม; notifications/ จัดการกล่องข้อความ Push และ SMTP; integrations/discord/ ดูแลช่องและคิวงาน; integrations/control/ เป็น API สำหรับ panel หลัก; public/groups.js เป็น UI กลุ่ม

ฝั่งบอท integrations/calendar/client.js เรียก API และ worker.js รับงานเฉพาะเครื่องที่ทำงาน web/routes/calendar-admin.js เป็น proxy ส่วน web/public/calendar-admin.js เป็นหน้าจัดการ

Browser API ใช้ /api/groups, /api/group, /api/invitations และ x-calendar-group เพื่อเลือกกลุ่ม แต่ header ไม่ใช่สิทธิ์ Server API แยก /internal/v1/bot และ /internal/v1/control มี Bearer key คนละชุด ดู route modules สำหรับ method และ validation จริง ไม่ตั้งกุญแจใน environment variable ที่เผยแพร่ไปหน้าเว็บ

## วันทั่วไปที่ใช้ร่วมกัน

ทุกกลุ่มแสดงวันหยุดและวันสำคัญจากข้อมูลส่วนกลางเดียวกัน ระบบเก็บแต่ละรายการเพียงครั้งเดียวในตาราง events ด้วย data_scope=shared ส่วนกิจกรรมที่สมาชิกสร้างและกิจกรรมเดิมที่นำเข้าเป็น data_scope=group จึงยังอยู่เฉพาะกลุ่มของตัวเอง ไม่คัดลอกข้อมูลเมื่อสร้างกลุ่มใหม่

API รวมข้อมูลกลางกับกิจกรรมของกลุ่มที่ผู้ใช้มีสิทธิ์อ่านด้วย UNION ALL โดยสองชุดไม่ทับกัน และมี partial index สำหรับข้อมูลกลางและแต่ละกลุ่ม การอัปเดตข้อมูลกลางส่งผลต่อทุกกลุ่มทันทีที่เรียกข้อมูลใหม่ ตัวกรองหมวดหมู่ยังใช้การตั้งค่าของผู้ใช้ การเตือนผ่านเว็บและคิว Discord ใช้ชุดข้อมูลร่วมเดียวกันและการตั้งค่าของแต่ละกลุ่ม กลุ่มส่วนตัวยังคงตรวจสิทธิ์เดิม
